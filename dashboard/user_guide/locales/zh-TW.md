## 系統介紹

本供應鏈規劃展示系統可協助你了解需求、產能、庫存與短缺對計畫的影響。你可以準備資料、比較情境並調查結果，作為營運決策的參考。相同資料與假設會得到相同結果；採取行動前，請先確認資料與假設是否符合實際狀況。

### 系統目的、使用者與限制

本系統可準備規劃輸入、檢查資料涵蓋及明確假設、執行支援的規劃情境、檢視風險訊號、調查已發布佐證，並比較兩個情境。適用使用者包括規劃人員、供應鏈分析人員及熟悉資料單位／來源的審查者。系統不會推算缺漏需求、生產標準、實際庫存，也不會替使用者選擇最佳行動。

### 完整操作流程

1. 選擇規劃模型。多週庫存／工作負荷軌跡使用**連續週次規劃**；需要各週分別計算時使用**單週獨立分析**。
2. 在連續週次模式選擇 CSV 上傳／欄位對應，或指定現有 JSON 設定路徑；檢查並驗證資料就緒狀態。
3. 檢查 READY、假設與單位後才明確執行規劃；也可直接載入已發布的連續週次規劃結果資料夾。
4. 在概觀、情境比較、分配明細、規劃風險摘要及情境取捨分析檢視所選結果。
5. 視需要下載已發布結果檔、調查佐證或比較匯出。

### 導覽與語言

點擊畫面右上角的語言選單，即可選擇 English 或繁體中文。切換後，系統介面與使用說明會同步更新。開啟或關閉使用說明後，可以繼續原本的規劃作業。規劃模型位於側邊欄；結果以分頁呈現。切換語言不會改變資料或規劃結果。

### 重要概念

關鍵績效指標（KPI）用來摘要呈現服務與產能表現。CSV 是可用試算表軟體開啟的表格檔；ID 表示識別碼。READY 表示必要資料檢查通過；BLOCKED 表示仍有問題，修正後才能執行。N/A 表示無法計算或不適用。資料檢查通過不等於業務核准。

- **情境（Scenario）** — Run 中一組命名的需求／產能假設。CSV 流程建立 Baseline、Demand Surge、Capacity Disruption、Combined Stress。
- **規劃執行（Run）** — 一次規劃執行，保存設定、唯一識別碼與完成的結果。載入 Run 只讀取分析，不會重新執行規劃。
- **連續週次與單週獨立模式** — 連續週次模式會在週日結束的週次間承接庫存與欠單並計算模型服務指標；單週獨立模式以數量產能各週獨立分配，KPI 定義不同。
- **佐證（Evidence）** — 已保存的來源／模擬結果檔案；依每份資料原本記錄的產品、工廠或週次篩選。觀察結果不是因果證明。

### 系統不提供的能力

系統不產生需求預測、不最佳化規劃、不推薦最佳行動、不連接 ERP、不提供登入驗證，也不保證 Community Cloud 檔案永久保存。使用者上傳資料不會永久留存。結果取決於明確輸入的涵蓋範圍、單位、假設及模型選擇。

## 營運總覽

營運總覽是單週獨立分析的結果介面，用來檢視準備好的單週獨立模式情境與分配結果。它與會承接庫存與欠單的連續週次規劃及其服務 KPI 分開。

### 使用目的與時機

需要快速查看現有單週獨立模式資料的情境概觀或工廠／產品分配明細時使用 Dashboard。若需要跨週承接庫存與欠單，請改用連續週次規劃。

### 輸入與控制項

側邊欄提供開始日期（預設 `2017-01-01`）、結束日期（預設 `2017-12-31`）、需求增加幅度（預設 10%、最小 0）、產能減少幅度（預設 20%、範圍 0–100%），以及從既有規劃快照選擇受影響的工廠。工廠選項由已準備的規劃資料讀取。這些控制項供單週獨立模式規劃執行使用，不會修改目前載入的連續週次 Run。

單週獨立模型會依日期範圍儲存結果。若該期間的結果資料夾已存在，系統會顯示警告並停用執行按鈕，以保護既有檔案。預先準備的 2017 年結果已經存在。請只選擇實際需要分析的期間，不要為了繞過保護而更改日期。

### 分頁與輸出

1. **情境概觀** — 選擇情境，檢視 Service Level、Capacity Utilization、Allocation Rate、Backlog 及狀態卡片。資料與圖表支援存在時會顯示工廠產能利用圖。
2. **情境比較** — 檢視各情境準備好的 KPI 及相對 Baseline 的變化；比率差以百分點顯示。若選用圖表功能不可用，部分圖表會改為文字摘要。
3. **產能分配明細** — 選擇情境及工廠，檢視分配列與工廠摘要；摘要中的共享工廠週產能只計算一次。

### 單週獨立模式結果解讀

單週獨立分析 `Service_Level` 是「分配數量 ÷ 淨需求」，代表單週獨立模型的生產分配涵蓋程度，不是連續週次 `Horizon_Service_Level`，也不是準時服務率。單週獨立模式每週獨立計算，不代表庫存或欠單會帶到下一週。情境比較只描述模型結果，不會推薦行動。

### 常見誤解

- 將單週獨立分析 `Service_Level` 直接與連續週次服務 KPI 比較。
- 假設單週獨立模式庫存或欠單會跨週承接。
- 把產能利用率或分配率當作服務保證。
- 未確認將使用的資料與儲存位置就執行單週獨立模式規劃。

## 規劃作業

連續週次規劃會依明確輸入建立逐週規劃結果。當規劃期間需要讓庫存、期初欠單、外部到貨、工作負荷係數與工廠每週共用產能納入考量時使用。系統產生的是情境結果，不會預測需求或選出最佳計畫。

### 選擇模型與輸入方式

`連續週次規劃` 是預設模式，會將期末庫存／欠單帶到下一週，並依工廠與週套用工作負荷產能，適合多週規劃。`單週獨立分析` 以數量產能各週分別計算，不跨週承接庫存／欠單；適合希望各週分別分析的使用者。

連續週次模式有三種操作：

- **上傳 CSV 資料** — 上傳必填與選填 CSV，對應來源欄位至系統所需欄位、完成需求資料分類、檢視資料檢查結果，最後明確選擇**驗證輸入**或**驗證並執行規劃**。
- **使用既有 JSON 設定** — 若已有專人準備設定檔，才使用此選項。JSON 是一種文字設定檔格式。請輸入執行系統的電腦上的檔案位置；你自己電腦上的檔案不會自動出現在雲端系統。若不確定位置，請詢問設定檔提供者。此處沒有 JSON 上傳按鈕。
- **載入已發布 Run** — 在側邊欄輸入 Run 資料夾路徑。資料夾需有通過檢查的 `run_manifest.json` 與必要結果檔案。載入不會執行規劃。

### CSV 資料集與欄位

可從表單下載 CSV 範本。完成欄位對應後，來源表頭不必改名；請確認對應語意正確。

| 資料集 | 必要系統所需欄位 | 選填欄位／注意事項 |
|---|---|---|
| Products（產品） | `Product_ID`、`Product_Name` | `Quantity_Unit`、`Planning_Priority` |
| Plants（工廠） | `Plant_ID` | `Plant_Name` |
| Product to plant mapping（產品工廠對應） | `Product_ID`、`Plant_ID` | 定義產品與工廠的支援關係 |
| Demand — WEEKLY | `Product_ID`、`Demand_Qty`、`Week` | 可有 Plant、Status、單位及來源識別；Status 需分類，或明確聲明整份檔案已是合格需求 |
| Demand — ORDER_LINES | `Product_ID`、`Order_Line_ID`、`Date`、`Quantity`、`Status` | 每個狀態需選資格；檔案必須完整涵蓋所述歷史，請確認期間內的訂單均已完整提供 |
| Optional planning priorities（選填優先順序） | `Product_ID`、`Planning_Priority` | Products 未提供時使用；不要重複提供優先順序來源 |
| Weekly workload capacity（每週工作負荷產能） | `Plant_ID`、`Week`、`Capacity`、`Workload_Unit` | 可有產能／係數版本；單位需相容 |
| Product workload factors（產品工作負荷係數） | `Product_ID`、`Workload_Factor`、`Workload_Unit` | 可有係數版本及數量單位；係數需大於零 |
| Initial inventory（期初庫存） | `Plant_ID`、`Product_ID`、`Beginning_Inventory` | 可有 `Week`、`Quantity_Unit`、`Beginning_Backlog`；若填週次，須為規劃第一週 |
| Opening backlog（期初欠單） | `Plant_ID`、`Product_ID`、`Beginning_Backlog` | 可有 `Quantity_Unit`；勿與 Initial inventory 內嵌的餘額重複 |
| External receipts（外部到貨） | `Receipt_ID`、`Plant_ID`、`Product_ID`、`Week`、`External_Receipts_Qty` | 可有 Scenario、Quantity_Unit；Week 是可使用到貨的週次 |

CSV 模式固定需要 Products、Plants、Product to plant mapping、Demand。其他資料集若未提供，需選擇相對應且受支援的明確假設。單位、產品及工廠識別需一致。只有表頭或不完整的檔案不能證明零需求。

### 欄位對應與需求資料分類

選擇 `WEEKLY` 表示每列需求已按週日結束的週彙總；選擇 `ORDER_LINES` 表示日期、產品、訂單明細識別碼、數量及狀態的逐筆訂單。對應每個必要系統所需欄位至不同來源欄位。系統會預覽標題和資料並提出建議，請逐項確認。

若需求含 Status，需把每個狀態分類為 Qualified 或 Excluded。若週需求不含 Status，需明確聲明檔案已只包含合格需求。ORDER_LINES 也要明確聲明檔案完整涵蓋所述歷史；此控制會獨立於狀態分類顯示。`USER_PROVIDED` 代表輸入來源，不代表歷史真實性經過獨立驗證。

### 規劃設定與假設

以下為 CSV 表單實際預設值及可填寫範圍。部分數值是設定標籤或單位，不是物理限制。驗證還會檢查有限數值、日期、鍵值、資料涵蓋及單位相容性。

| 欄位 | 用途、單位、預設值與範圍 | 對結果的影響／範例 |
|---|---|---|
| 規劃開始週／結束週 | 週日結束日期；若已映射需求日期，依資料建議；沒有需求日期預覽時，兩者預設為下一個週日。開始不得晚於結束，兩者都必須是週日。 | 定義規劃期間。例如選取連續四個週日作為四週期間。 |
| 需求資料的解讀方式 | `USER_PROVIDED_PLAN`（預設）或 `RETROSPECTIVE`，非數值欄位。 | 說明輸入代表使用者提供的計畫或歷史資料回推；兩者都不會產生預測。 |
| 本次規劃設定名稱 | 必填非空文字；預設 `streamlit-user-upload-v1`。 | 在資料檢查與規劃紀錄中保存這次設定的名稱。例如 `FY27-weekly-plan-v1`。 |
| 數量調整步長 | 數量單位；預設 0，最小 0，欄位未設上限；必須是有限且非負數。 | 0 表示可連續調整；正值表示共用包裝／數量步長。例如 5 代表分配數量依 5 單位遞增。 |
| 需求增加幅度 | 百分比；預設 10%，最小 0，欄位未設上限。 | 套用至 Demand Surge、Combined Stress。10% 表示需求乘數 1.10。 |
| 產能減少幅度 | 百分比；預設 20%，範圍 0–100%。 | 套用至 Capacity Disruption、Combined Stress 中選定工廠；100% 表示該情境的受影響產能全數減少。 |
| 受影響工廠 | 從上傳工廠識別碼多選；有可用工廠時預設選第一個。 | 僅限制產能中斷影響的工廠；執行前確認識別碼及範圍。 |
| 短缺政策 | 預設 `CARRY_FORWARD`；也可選 `LOST_SALES`。 | Carry 將未履約義務留作欠單；Lost Sales 將當週未服務需求記為流失且不承接。此政策不接受非零期初欠單。 |
| 備用產品數量單位 | 文字；預設空白。 | Products 沒有可用數量單位且需要明確假設時才填；例如實際單位 `case`，不可猜測。 |
| 假設優先順序 | 勾選框預設關閉；優先順序預設 2，選項 1–3（1 較低、3 較高）。 | 只有 Products 與 Optional planning priorities 都沒有優先順序，且勾選後才套用。 |
| 統一工作負荷係數 | 勾選框預設關閉；係數預設 1.0、最小 0.000001、步長 0.25；工作負荷單位預設 `EqWU`。 | 假設每單位產品消耗的合成工作負荷；屬於明確假設，不是實測生產標準。 |
| 假設期初庫存為零 | 勾選框預設關閉。 | 缺少 Initial inventory 檔案時，以明確的零期初庫存假設取代。 |
| 假設期初欠單為零 | 勾選框預設關閉。 | 沒有欠單餘額時明確假設零；不會清除已提供餘額。 |
| 聲明不建模外部到貨 | 勾選框預設關閉。 | 沒有 receipts 檔案時，明確聲明不建模外部到貨。 |
| 合成產能目標利用率 | 勾選框預設關閉；目標預設 0.75，範圍 0.01–1.00，步長 0.05。 | 依選定期間的合格需求推算合成工作負荷產能。此假設會標示為合成產能，不是實測工廠產能。 |

### 資料檢查、驗證與執行

1. 檢查資料集狀態，修正 CSV 讀取錯誤或重複欄名。
2. 完成系統所需欄位對應與需求資料分類分類。
3. 設定週日日期、需求解讀、情境假設與所需明確假設。
4. 選擇**驗證輸入**。READY 表示必要資料檢查通過；仍須查看警告、資料來源、假設、衍生值及不可用能力。BLOCKED 會列出待修項目。驗證不會建立 Run。
5. 確認 READY 後才選擇**驗證並執行規劃**。系統會再次驗證，執行時才暫存上傳資料，成功後發布新的 Run。失敗執行不等於成功發布。

CSV 表單建立 Baseline、Demand Surge、Capacity Disruption、Combined Stress。情境乘數依輸入百分比計算，短缺政策套用到情境。成功後顯示 規劃識別碼（Run ID）／資料夾，並提供 `performance_result.csv`、`allocation_result.csv`、`run_manifest.json` 下載。

### 結果解讀與常見錯誤

選擇情境後，使用概觀、情境比較、產能分配明細、規劃風險摘要及情境取捨分析。切換情境只是改變檢視，不會重新規劃。請依 KPI 詞彙表的單位及明細層級解讀。期末庫存／欠單是存量，不可跨週加總。`CARRY_FORWARD` 的短缺成為欠單；`LOST_SALES` 則是流失數量。`LOST_SALES` 下的零欠單不代表需求全數服務。

常見錯誤包括把 READY 當成業務核准、映射到名稱相似但意義不同的欄位、把缺少週次視為零需求、混用數量與工作負荷單位、重複計入期初欠單，或假設系統會預測需求。

### 已發布 Run 與儲存限制

開啟已儲存結果時，系統會確認規劃紀錄與必要結果檔案是否完整、是否曾被更動。如果原始輸入檔案遺失或改變，也會顯示提示。請使用連續週次規劃的結果資料夾，勿混用單週獨立模式結果。重要結果請自行下載保存；Community Cloud 重新啟動或更新後，檔案可能消失。

## 根因與營運風險分析

根因與營運風險分析呈現所選規劃結果中的佐證資料與風險訊號。可用來檢視產品、工廠、週次周邊出現的情形，但不能證明因果責任。

### 入口與必要輸入

載入連續週次規劃結果，開啟**規劃風險摘要**，再選擇產品風險、工廠瓶頸、情境風險或根因調查。產品／工廠風險操作可帶入調查選擇；情境比較與決策分析也可將比較側別和產品帶入同一調查流程。

必要內容為有效 Run、情境及可用調查記錄。依調查路徑選擇產品、工廠及週日結束週次。若佐證不可用，請查看來源狀態，不要把缺少資料列視為零。

### 檢視觀察與佐證

調查頁會顯示選定週產品觀察、共享工廠週產能、相關觀察及產品相鄰週軌跡；也可列出共同使用選定產能池的產品。每份佐證依原本記錄的產品、工廠或週次篩選；需要明細時使用相應下載。

匯出中的 `Investigation_*` 欄描述目前畫面的選擇，不會改變來源資料原有的明細層級。每週 CSV 記錄識別碼代表來源資料列，不一定是業務訂單。情境需求增量不會虛構來源訂單。

### 解讀結果與常見錯誤

將風險標記和同時出現的觀察視為待審查訊號。優先順序、工作負荷、共享產能及另一產品的短缺，不能證明某產品造成其他產品的結果。產品數量與工廠週工作負荷產能使用不同單位，不可直接比較。期末庫存與欠單是單週存量，不可跨週加總。

若原始來源檔案遺失或檔案曾被更動，系統可能仍顯示經驗證的已發布佐證，但會標示來源可用性。缺少原始來源不會以重建資料取代佐證。需要原始明細時請下載相應結果檔案。

## 情境比較與決策分析

情境比較與決策分析比較已載入連續週次規劃結果中兩個情境的差異。用來描述模型結果與可比較程度，不會替使用者選出最佳行動。

### 選擇參考、候選與群組

開啟**情境取捨分析**，明確選擇 參考情境（`Reference Scenario`）與候選情境（`Candidate Scenario`）。系統不會預設 Baseline；候選清單會排除參考情境。再選擇零個或多個優先順序（1–3）定義固定參考群組。ALL 為完整範圍；SELECTED 為符合所選 Reference 優先順序的產品；COMPLEMENT 為其餘產品。選取群組為空時，SELECTED 可能沒有成員或顯示 N/A。

比較範圍使用完整已儲存規劃結果期間、產品範圍及納入規劃的工廠。Candidate 即使優先順序不同，群組成員仍依 Reference 定義。介面會顯示優先順序變更和群組成員。

### KPI 與可比較性

摘要比較 Horizon Service Level、Terminal Backlog、Lost Sales、Allocated Workload、Unmet Workload，並提供 ALL／SELECTED／COMPLEMENT。展開各指標可比較原因、工廠產能池內容及佐證來源清單查看細節。

Delta 為 **Candidate − Reference**。服務率本身是比例；服務指標差異以百分點呈現；數量／工作負荷差異保留各自單位。例如服務率由 0.60 變為 0.75，差異為 +15 個百分點。正值不一定較好：工作負荷或欠單增加可能不利。系統僅描述結果，不選擇偏好的計畫。

`COMPARABLE` 表示可比較；`DESCRIPTIVE_ONLY` 表示僅供描述，需留意限制；`BLOCKED` 表示無法比較；`POLICY_CONTRAST` 表示短缺政策不同；`N/A` 表示無法計算或不適用。解讀數值前請先讀原因。短缺政策或其他條件輸入不同，可能令結果只能描述或無法比較。`LOST_SALES` 下的零欠單本身不代表服務改善。

### 接續調查與下載結果

選一個比較產品，再選擇要調查 Reference 或 Candidate。此操作只會預先選好調查的產品與情境，不建立 Run。可下載比較指標、產品群組成員、佐證來源清單、比較設定。下載檔案會包含對應的比較識別碼與設定；切換語言不會更動 CSV 欄名或下載資料中的值。

### 常見錯誤

- 假設已自動選擇 Baseline，或把相同情境互相比較。
- 認為產品優先順序群組會依 Candidate 的優先順序重新分組。
- 把百分點差異誤讀成百分比變化。
- 不看原因就解讀僅供描述或無法比較數值。
- 不依指標類型、單位、群組及比較狀態解讀 Delta 正負號。

## KPI 與專業詞彙

以下說明連續週次規劃的指標用途與定義。數值依顯示明細層級彙總；分母為零時，比率可能是 N/A。單週獨立分析指標有另一套定義，請明確標示為單週獨立分析。

### 服務與需求指標

| 名稱 | 定義與單位 | 重要限制 |
|---|---|---|
| 期間服務水準（`Horizon_Service_Level`） | 規劃期間內產生的需求在期間結束前服務的數量 ÷ 期間合格需求總量。比率。 | 包含期間內欠單後續履約；不含規劃開始前的期初欠單。不是準時率。 |
| 每週服務水準（`Weekly_Service_Level`） | 當週服務的當週需求 ÷ 當週需求。比率。 | 不計入後續週補服務；當週需求為零時是 N/A。 |
| 生產涵蓋率（Production Coverage Rate） | 內部生產量 ÷ 計算出的生產需求。比率。 | 不是需求服務 KPI；庫存或外部到貨可能在未生產時滿足需求。 |
| 當週未滿足數量（Current Unfulfilled Quantity） | 當週沒有服務的當週需求。數量。 | 之後仍可能補足；不等於期末欠單。 |

例：當週需求為 8、當週服務 5，Weekly Service Level = 5/8 = 62.5%。若其餘 3 在後續週服務，Horizon Service Level 可達 100%，但每週結果仍是 62.5%。

### 產能、庫存與短缺

| 名稱 | 定義與單位 | 重要限制 |
|---|---|---|
| 產能利用率（Capacity Utilization） | 分配工作負荷 ÷ 可用工作負荷產能，按唯一產能池彙總。比率。 | 工廠週共享產能只計一次；產能為零時是 N/A。 |
| 已分配工作負荷（Allocated Workload） | 內部生產量 × 產品工作負荷係數。工作負荷單位。 | 外部到貨不消耗此工作負荷；係數、版本及單位需相容。 |
| 未滿足工作負荷（Unmet Workload） | 未完成生產需求換算成的工作負荷。工作負荷單位。 | 是跨週流量，不是期末欠單。 |
| 欠單（Backlog） | `CARRY_FORWARD` 政策下承接的未履約義務。數量存量。 | 依正確週次／明細層級檢視；不可跨週加總期末存量。 |
| 期末庫存（Ending Inventory） | 到貨、生產、履約後剩餘可用庫存。數量存量。 | 不可跨週加總；沒有自動補貨或安全庫存目標。 |
| 流失銷售數量（`Lost_Sales_Qty`） | 選擇 `LOST_SALES` 時未服務且不再承接的當週需求。數量。 | 不是流失營收。`CARRY_FORWARD` 下流失銷售為零不表示沒有短缺。 |

### 情境、Run 與比較

**規劃情境（Scenario）**

每次規劃可以設定不同的需求、產能與短缺處理方式。這些設定形成具名的規劃情境，方便比較不同條件下的結果。

**規劃執行（Run）**

一次執行會保存設定與結果，並附上唯一的規劃識別碼（Run ID）。載入結果可繼續分析，不會重新執行規劃。

**參考情境／候選情境（Reference / Candidate）**

參考情境是你選擇的比較基準；候選情境是要與它比較的對象。差異值（Delta）等於候選減去參考。

**產品群組（Cohort）**

ALL 包含全部產品；SELECTED 是符合所選參考情境優先順序的產品；COMPLEMENT 是其餘產品。

**百分點（Percentage point）**

服務率從 60% 上升到 75%，表示增加 15 個百分點。

**單週獨立分析服務水準（Service Level）**

分配數量除以淨需求，表示單週獨立模式生產分配涵蓋程度程度；與連續週次模型的期間服務水準定義不同。

## 常見問題與排除方式

先查看資料檢查錯誤與來源狀態。除非使用者明確選擇系統提供的特定假設，否則不可把缺少或不可用輸入默默當成零。

### 缺少輸入或資料檢查為 BLOCKED

確認四種固定必填 CSV 都已提供。其他缺少資料集需上傳，或選擇該資料集特定且受支援的假設。查看完整錯誤及來源／假設區塊。假設零庫存、零欠單或沒有到貨是模型假設，不是發現歷史真相。

### CSV 無效或欄位對應錯誤

確認檔案有標題與資料列、欄名唯一、編碼可讀、WEEKLY／ORDER_LINES 格式正確、來源欄位一對一對應、數量有限且非負、日期有效、單位相容且產品、工廠與週次組合沒有不允許的重複。欄名相似但含義不同時請重新對應。不要將識別碼欄映射為數量欄。

### 需求狀態或規劃期間問題

每個來源狀態都必須分類。沒有 Status 的 WEEKLY 檔案須明確聲明已合格。日期必須是週日，且開始不得晚於結束。ORDER_LINES 需明確聲明是完整歷史擷取，即使同時已完成狀態分類；不要宣稱部分訂單列涵蓋完整歷史。

### 產能或係數假設

請提供相容的 Weekly workload capacity 與 Product workload factors，或選擇受支援的明確係數／合成產能假設。合成產能依合格需求和目標利用率推算，並會標示為假設；不是實測生產產能。

### 規劃未執行或失敗

驗證與執行是不同操作。BLOCKED 會阻止執行。若執行失敗，讀取摘要與技術細節、檢查路徑和輸入，再修正後重試。確認輸出位置可寫入，且使用的不是單週獨立分析路徑。失敗嘗試不是已發布結果。

### 找不到已儲存規劃結果或佐證不可用

請輸入包含已完成規劃結果的資料夾，而非單一 CSV 或其上層目錄。資料夾須包含規劃紀錄（`run_manifest.json`）與所有必要結果檔案。若不知道位置，請向資料提供者確認執行系統的電腦上，結果資料夾的正確位置。原始輸入資料遺失時，即使結果仍可讀取，也可能無法追查來源明細。

### 根因與營運風險分析沒有結果

確認選擇的規劃結果、情境、產品、工廠與週次有對應的佐證資料。沒有資料不代表零需求或零風險。檢查來源可用性／檔案完整性訊息，以及所選項目是否在 Run 範圍內。

### 情境比較與決策分析被阻擋或不易比較

在同一次已載入的規劃結果內選擇不同的 Reference 與 Candidate。查看指標可比較原因、政策差異、輸入差異及固定 Reference 群組。N/A 表示此範圍無法計算或不適用；BLOCKED 或 DESCRIPTIVE_ONLY 必須閱讀原因。系統不會自動推薦情境。

### 語言、目錄導覽與未提交表單值

使用右上角語言選單切換語言；目前閱讀的章節會保留。閱讀使用說明後，可以回到尚未送出的規劃表單繼續編輯。若欄位內容意外消失，請先停止執行規劃，記下欄位名稱與操作順序，再尋求協助。

### 常見操作錯誤

- 假設缺少的資料列等於零需求。
- 把來源標記或合成分類當成獨立驗證的真實資料。
- 將單週獨立分析與連續週次規劃 KPI 當作同一公式比較。
- 跨週加總庫存／欠單存量。
- 把風險觀察當成因果歸因。
- 不看 Delta 符號、單位、群組和可比較狀態就解讀情境比較與決策分析。
- 假設上傳、驗證結果、產生的規劃結果 或雲端暫存檔案會永久保存。
