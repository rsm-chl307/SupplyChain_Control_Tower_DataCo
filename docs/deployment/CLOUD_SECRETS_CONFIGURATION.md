For a later, separately authorized paid release, the Owner enters `OPENAI_API_KEY` in the existing Streamlit application's Cloud App Settings → Secrets. The Python server may read it only when an authorized paid request is actually executed. Do not commit `.streamlit/secrets.toml`, place a key in a command, store it in browser/session state, or send it to Codex. The current `StreamlitSecretsCredential` interface returns a sanitized error if the key is missing or invalid; public features do not call it.

The future AI password verifier uses two separate Secret entries: `AI_ACCESS_SALT_HEX` (32 random bytes, hex) and `AI_ACCESS_SCRYPT_HEX` (32-byte scrypt output, hex). Generate them on an Owner-controlled machine using a hidden password input and local script reviewed at the later configuration stage; do not paste the password or verifier into chat, repository or reports. The verifier is not a plaintext password, but it remains sensitive configuration and must stay in Cloud Secrets. No actual password or verifier was created here.

Cloud Secrets protect values from the Git repository, **not from deployed application code**. Owner review of exact deployment source and dependencies is mandatory before release. Codex must not have Cloud Secrets settings access or production deployment write access. A production key is not required for the public Demo or Stage 0–3 tests.
