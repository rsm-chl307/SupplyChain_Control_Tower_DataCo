# AI Decision Copilot V1.2 — Independent Technical and Security Review

Audit date: 2026-11-21 UTC. Scope: current development working tree, offline and synthetic only. This is an audit of the present implementation, **not** permission for P5 or P6. The implementation files are largely untracked or dirty; HEAD alone is not the reviewed product.

## 1. Executive Summary

The local offline chain is coherent: a pinned synthetic harness issues a live Context; V1.1 constructs and validates a source-bound Brief; P2 hashes a canonical request; P3 separately authenticates an Owner and atomically reserves one allowance in SQLite; P4 previews only a Fake Provider result after P1 validation. The real provider adapter is deliberately blocked. The selected synthetic-only tests exercise the principal negative controls, including cross-context rejection, digest invalidation, process concurrency and UNKNOWN retention.

**Overall decision: READY FOR P5 PLANNING; NOT READY FOR P5 AUTHORIZATION OR A PAID CALL.** Two high-severity P5 readiness findings concern fail-closed ledger continuity and the absence of actual usage/cost reconciliation. The local trusted-process assumption is material. Cloud runtime and a real SDK/model remain unverified. No critical finding or current path to a paid call was found. This decision does not approve a production model, budget, provider transfer, SDK installation, Cloud port or execution.

## 4. Architecture Review

The actual dependencies run `SyntheticHarness` (`src/synthetic_context.py`) → `load_context`/`SourceBundle` (`src/ai_brief/adapter.py`) → `validate_draft`/`ValidatedBrief` (`src/ai_brief/validation.py`) → P2 `build_request` → P3 `LocalExecutionGate`/SQLite → P4 `render`; provider results return through P1 `classify_response` before `render_validated` (`dashboard/copilot_view.py:245-257`). The UI does not issue a paid reservation or call `OpenAIResponsesAdapter.execute`. Streamlit session state holds handles and an approval reference; `approval_status` and ledger status requery SQLite (`dashboard/copilot_view.py:228-244`). Service binding re-creates the request from the live Brief (`src/ai_copilot/execution_gate.py:18-46`).

The seam is suitable for offline development, but P3's public store/ledger classes are lower-level primitives, not an authorization boundary against a malicious local Python caller (finding V12-SEC-003). The future dispatcher must own the trusted service and stable ledger path. Exceptions generally fail closed in the P4 view; an invalid Fake result follows the error branch. No multi-turn model history, arbitrary provider tool, recommendation execution or automatic retry path was found.

## 6. Trusted Context and Data Isolation

`src/synthetic_context.py:24-35` pins fixture filenames and SHA-256 values. `_directory` walks components with `O_NOFOLLOW` (`:79-90`); `_read_at` opens approved names under a directory file descriptor and bounds bytes. `SyntheticHarness` makes a private `TemporaryDirectory`, verifies fixture hashes and `SYNTHETIC_DEMO`, writes copied inputs only under that directory and constrains the runner output to its new `runs` directory (`:93-134`). `_inspect` checks Run, manifest, artifact paths, checksums, row counts, scenario and published lifecycle (`:148-199`). Issuance uses an HMAC, registry identity, random nonce, exact Run/manifest/artifact/scenario binding and a 300-second monotonic expiry (`:201-242`). `load_context` has no caller Run path (`src/ai_brief/adapter.py:111-143`). Snapshot bytes are held in an issued `SourceBundle`, whose fresh revalidation rejects mutation (`:44-74`); `ValidatedBrief.verify` checks issuer registry, live source and digest (`src/ai_brief/validation.py:9-22`). Source references resolve only within the validated Brief (`:69-81`).

Logical expiry is implemented and tested by forced clock/state conditions; explicit UI close and context replacement remove the owned workspace and are tested (`tests/test_synthetic_context_lifecycle.py:16-67`). The UI schedules a daemon `Timer(305, harness.close)` after the 300-second Context lifetime (`dashboard/copilot_view.py:95-108`). A full elapsed 305-second test, cleanup after process termination, refresh without explicit close and adversarial same-user process manipulation are **not verified**. The timer belongs to the local Python process; it is not a persistent cleanup service. Private temporary-directory permissions and no-follow reads are meaningful under the trusted-host assumption; they do not defend against a compromised local Python process.

## 7. P1 Response Contract Review

`src/ai_copilot/response_contract.py:13-58` builds closed objects (`additionalProperties: false`), required fields, enums and bounded arrays/text. `validate_response` checks live Brief, 32 KiB response size, duplicate JSON keys, non-finite values, schema, Brief digest, evidence refs, unavailable sections, exact numeric slot value, unit and native grain, duplicate IDs, and absent-comparison trade-offs (`:83-154`). `classify_response` keeps refusal, incomplete, definitive error, UNKNOWN and validation failure out of the validated-success branch (`:157-165`). P4 renders numeric evidence from validated structured slots (`dashboard/copilot_view.py:127-135`). These are structural and provenance checks, **not semantic truth proof**.

The free-text rule rejects ASCII or Unicode digits in selected prose fields (`response_contract.py:142-146`) but does not parse spelled-out quantities or unsupported causal claims. A fresh synthetic-only probe changed the valid Fake summary to “Service improved by twenty percent.”; `validate_response` accepted it. This is V12-RESP-004. The schema also permits empty `evidence_refs` for qualitative claims, so a reference appearing in a response does not prove the surrounding interpretation. Human review remains mandatory before using any future paid advisory.

## 8. P2 Provider Architecture Review

`src/ai_copilot/provider.py:45-67` requires a live validated Brief, explicit model snapshot, 1–2500 output tokens and a 0–60-second timeout, and hashes canonical bytes containing Brief/digest, fixed instructions/version, response schema/version, privacy version and limits. The Brief digest and outbound request digest are separate fields. `call_arguments` checks the digest and duplicate provenance before forming a no-tools, no-stream, no-background, `store=False` Responses argument map; `required_client_options` asks for zero retries (`:83-104`). `FakeProvider` is local (`:69-76`). `OpenAIResponsesAdapter.execute` unconditionally raises `ProviderBlocked` (`:78-81`); no SDK client instantiation or credential read was found. Mock-shaped `interpret` differentiates incomplete/refusal/failed/unknown and invokes P1 validation before returning a successful result (`:107-127`).

The environment has no installed `openai` Python package (`importlib.util.find_spec('openai') == None` in this audit). Exact SDK runtime behavior, model-specific strict-schema support, provider errors/timeouts, token usage and billing are unverified. The implementation report records a 2026-11-20 official-documentation review, but this audit made no network request and did not revalidate current docs. `store=False` is a request flag, **not a zero-retention guarantee**. Actual outbound Brief fields must pass the P5 privacy decision (V12-PRIV-005).

## 9. P3 Owner Approval Review

`OwnerVerifier.from_environment` reads separate Owner salt/scrypt hex configuration; `derive` requires a 16-character password and uses scrypt; authentication uses constant-time digest comparison (`src/ai_copilot/approval.py:26-69`). Demo authentication is not referenced. `ApprovalStore.approve` requires an explicit password-bearing call, canonical request verification, short TTL and writes reference, digest, policy version, expiry, revocation/consumption and optional cost/pricing data to SQLite (`:107-150`). `ApprovalRecord.valid_for` rejects stale, mismatched, expired, revoked and consumed references (`:88-104`). `LocalExecutionGate.bind` compares a rebuilt live request before approving or reserving (`src/ai_copilot/execution_gate.py:18-46`), so Brief, instruction, model, schema, privacy or limit changes invalidate an old reference.

This is sufficient for the documented **cooperative, owner-operated local process** only. It has no rate limiting, OS identity proof, tamper-resistant verifier storage, host compromise defense or Cloud identity. The lower-level `ApprovalStore.approve` accepts a caller-supplied verifier rather than pinning the configured Owner identity; a malicious in-process caller could create a verifier it controls and bypass the intended service if a future dispatcher accepts such records directly. Current P4 uses `LocalExecutionGate` and there is no real dispatch. See V12-SEC-003.

## 10. P3 Durable Ledger Review

`src/ai_copilot/ledger.py:20-39` defaults model, ceiling and pricing basis to `None`; reservation rejects any unset/mismatched value. The SQLite table has a fixed campaign primary key, unique approval reference and single allowance (`:56-68`). `reserve` uses `BEGIN IMMEDIATE`, checks the exact digest, Owner approval lifecycle, cost and pricing, inserts the reservation and consumes the approval in one transaction, rolling back on failure (`:79-109`). Threads and separate forked processes are covered by `tests/test_ai_copilot_ledger.py:94-127`. Allowed transitions are reserved `NOT_STARTED` → `IN_PROGRESS` → `SUCCEEDED`/`FAILED`/`UNKNOWN`; all terminal states retain the record, and UNKNOWN cannot reset or automatically resubmit (`ledger.py:111-130`). SQLite state persists across session/process reopen in tests.

The guarantee is per stable, protected **single database file**. `ApprovalStore.__init__` and `ExecutionLedger.__init__` create missing tables at a caller-provided path (`approval.py:110-124`, `ledger.py:59-68`). A safe local probe with two fresh temporary SQLite paths observed `NOT_STARTED` for both and creation of the replacement file; no reservation or provider was used. A missing/replaced database therefore appears as a fresh unreserved campaign instead of fail-closed; this contradicts the design specification's missing/corrupt-ledger fail-closed requirement and is a P5 blocker (V12-LED-001). The ledger records maximum reserved cost but no observed provider usage, actual charge, request ID or reconciliation record (V12-COST-002). No crash-reconciliation procedure exists; a crash after `IN_PROGRESS` can leave that label indefinitely, though the allowance remains reserved (V12-LED-008). These are not paid-execution observations.

| Threat / asset | Existing control and evidence | Residual risk / recommendation |
|---|---|---|

## 16. Findings Register

**V12-LED-001 — HIGH, CONFIRMED; ledger continuity.** Location: `src/ai_copilot/approval.py:110-124`, `src/ai_copilot/ledger.py:59-77`. Evidence: constructors accept any non-memory path and `CREATE TABLE IF NOT EXISTS`; a new/missing file yields `status() == NOT_STARTED`. Expected: design specification §5 says a missing/corrupt paid ledger fails closed. Actual: a fresh path creates a fresh campaign. Impact: a future dispatcher could treat a replaced/misconfigured DB as an unused one-call allowance. Existing mitigation: fixed campaign uniqueness and SQLite transaction within one stable file; no dispatch today. Action: require provisioned, ownership/permission-checked DB identity and durable continuity/recovery policy; fail closed on loss/corruption. Authorization: separate P5/P3 remediation approval before code change. Release: blocks paid P5 authorization, not offline P4.

**V12-COST-002 — HIGH, CONFIRMED; cost accounting.** Location: `src/ai_copilot/ledger.py:42-53,63-68,111-130`; contrast `src/ai_copilot/provider.py:31-37`. Evidence: ledger persists reserved maximum cost and state only; provider DTO can carry usage/request ID, but no ledger field or reconciliation method records actual usage, actual charge, sanitized error/request ID. Expected: one paid acceptance must be auditable against the approved ceiling and actual outcome. Actual: reservation and terminal label exist without a cost/usage settlement trail. Impact: future paid call could not establish actual spend from its durable ledger, especially on ambiguous outcomes. Existing mitigation: default-unset cost policy prevents current reservation without explicit values; no provider dispatch. Action: define approved pricing estimator, durable usage/charge/request-ID reconciliation and UNKNOWN procedure before a paid call. Authorization: separate P5/P3 remediation approval. Release: blocks paid P5 authorization.

**V12-SEC-003 — MEDIUM, CONFIRMED; local caller trust.** Location: `src/ai_copilot/approval.py:126-139`, `src/ai_copilot/execution_gate.py:13-46`, `src/ai_copilot/ledger.py:79-109`. Evidence: low-level `ApprovalStore.approve` accepts a caller-supplied `OwnerVerifier`; `ExecutionLedger.reserve` accepts the resulting record without a live Brief. Expected: future dispatch calls the pinned `LocalExecutionGate` and does not treat direct store calls as Owner authorization. Actual: same-process callers can bypass that service convention. Impact: a malicious plugin or compromised Python process could forge authorization if future dispatch trusts the low-level records. Existing mitigation: trusted local process threat model; current UI uses service and real adapter is blocked. Action: make the future dispatcher sole entry point and bind store ownership to provisioned verifier/DB identity; test direct-call rejection or document trusted-only API. Authorization: separate P3 security-contract decision if changed. Release: P5 integration hazard; not a current external exploit.

**V12-RESP-004 — MEDIUM, CONFIRMED; prose quantity gap.** Location: `src/ai_copilot/response_contract.py:120-154`. Evidence: synthetic-only one-off probe accepted “Service improved by twenty percent.” in `executive_assessment.summary`; `tests/test_ai_copilot_response_contract.py:57-64` checks only digit prose. Expected: unsupported quantitative prose is rejected or marked for human review. Actual: the digit regex misses spelled quantities, and semantic support is not proven. Impact: a future AI result could convey an unsupported KPI change despite successful structural validation. Existing mitigation: Fake fixture is fixed; UI says advisory, human review required, structured numeric slots are exact. Action: add explicit policy for word quantities/causal claims and prominent human-review treatment; retain source-slot rendering. Authorization: P1/P5 remediation authorization. Release: blocks treating P1 validation as semantic approval in P5.

**V12-PRIV-005 — MEDIUM, CONFIRMED; outbound minimization mismatch.** Location: `src/ai_brief/builder.py:76-97`, `src/ai_brief/contract.py:102-111`, `src/ai_copilot/provider.py:57-61,93-98`; design specification §2/§5. Evidence: canonical Brief `source_manifest` includes `artifact_name`, `artifact_sha256` and `upstream_hashes`; adapter maps the whole Brief to `input`. Expected design prose says no source filenames or source-hash keys in outbound content. Actual outbound mapping includes provenance file names/hashes (though no raw CSV or source path). Impact: metadata disclosure and an unresolved data-minimization decision before provider transfer. Existing mitigation: only pinned synthetic fixture is allowed; IDs are aliased and raw source rows/paths are excluded. Action: owner decides whether this exact synthetic provenance is permitted for P5, or approves a revised outbound projection preserving local evidence validation. Authorization: explicit privacy/product decision and likely protected V1.1/P2 change. Release: P5 transfer blocker until resolved.

**V12-UX-006 — MEDIUM, CONFIRMED; incomplete response display.** Location: `dashboard/copilot_view.py:111-135`; P1 schema `src/ai_copilot/response_contract.py:40-57`. Evidence: renderer shows assessment, four claim groups, finding description/severity/slots and two limitation fields, but omits recommendations, trade-offs, further investigation and much confidence/impact/rationale content. Expected: users can inspect the complete validated advisory and its limitations before relying on it. Actual: nonempty fields would be silently hidden. Impact: incomplete explainability and misleadingly sparse human review in future P5. Existing mitigation: current Fake fixture sets these arrays empty; no recommendation execution. Action: render all validated sections with source refs and limitations or explicitly state hidden fields; add populated synthetic UI tests. Authorization: P4/P5 remediation approval. Release: P5 UX readiness gap; offline fixture preview remains bounded.

**V12-CLD-007 — MEDIUM, CONFIRMED source-level limitation; Cloud boundary.** Location: `dashboard/copilot_view.py:49-59`.
